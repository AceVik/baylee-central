# The dependency upgrade of 25 November 2026

*Owner, 25.11.2026:* "grade bitte überall alle crates/packages up und führe
major version migrations etc. aus, sammt audit, verbesserungsvorschlägen
etc." The approval is the last entry of `approved-packages.json`'s
`approvals`. One week after [the upgrade of 18 November](upgrade-2026-11-18.md)
little had moved, and nothing enters the graph that was not in it before.

## What moved

- **Direct dependencies.** `sha2` 0.11.1 → 0.11.2 (every crate that hashes),
  `hyper` 1.12.0 → 1.13.0 (`central-http`'s listener), and the one major
  step: `central-http`'s `base64` 0.22.1 → 0.23.1 (the push socket's
  `Sec-WebSocket-Accept` and the ranked socket's upstream key). `base64`
  0.23.1 was compiled already, through `jsonwebtoken` 12 and `leptos`; its
  `Engine` API is the one `central-http` used, so no source changed. 0.22.1
  stays in the graph through `ece` and `sqlx-core`.
- **The lock file**, within each crate's own requirements: 32 packages, among
  them `zerocopy` 0.8.65, `pin-project` 1.2.0, `pin-project-lite` 0.2.18,
  `hashbrown` 0.17.2, `zlib-rs` 0.6.9, `crc32fast` 1.5.6, `anyhow` 1.0.105,
  `toml` 1.2.3 and `arrow` 60.2.0 (the latter only in the lock, through
  `sea-orm`'s optional parts).
- **The committed WebAssembly** (`crates/central-web/crypto/`): `sha2`
  0.11.2 and `pin-project-lite` 0.2.18 are in `central-web-crypto`'s graph,
  so the module was rebuilt with `cargo xtask wasm` on x86-64 Linux.
- **The browser test suites** (`crates/central-web/browser/`, development
  only): `@playwright/test` 1.65.1, `@axe-core/playwright` 4.14.1,
  `@types/node` 24.19.4 (the newest for Node 24, which CI runs), `oxlint`
  1.95.0. `npm audit` finds nothing.
- **CI's checkers and actions**: `cargo-audit` 0.22.2 → 0.23.0,
  `cargo-deny-action` v2.1.1 → v2.1.4 (cargo-deny 0.20.2 → 0.22.1),
  `actions/setup-node` v7.0.0 → v7.1.0, all pinned by commit as before.
  Both checkers pass on this tree at the new versions. Every other action
  was already at its newest release.

## Held back, on purpose

- `opaque-sha2` (`sha2` 0.10.9), `rand` 0.8.8 and `getrandom-legacy`
  (`getrandom` 0.2.17): as on 18.11., `opaque-ke` 4.0.1 is the newest stable
  release. 5.0.0-pre.0 (13.11.2026) is a pre-release, and a new major of the
  OPAQUE crate must not change the record under enrolled accounts unreviewed.
- `leptos` 0.9.0-rc1: still the newest 0.9 release.
- `typescript` 7.1.0-beta: the beta this suite chose; 7.0.2 is the newest
  stable and older.
- `matchit` 0.8.6 and `generic-array` 0.14.9: held by `axum` 0.8.9's and
  the RustCrypto 0.10 crates' own requirements.

## New code that is not this repository's

None: every package in the new lock file was in the old one, at another
version, and no new feature is enabled on any of them. No build script is
new.

Licences and advisories: `cargo deny check` and `cargo audit --deny warnings`
pass with the `chrono` exception ([chrono-advisory](chrono-advisory.md)) as
before. This is the implementing agent's inventory, not a source audit of the
packages.

## Rust 1.100.0, 26 November 2026

The pinned toolchain moved from 1.99.0 to 1.100.0 (released 9 November
2026): `rust-toolchain.toml`, the nine installs in `ci.yml` and the two in
`release.yml`. `rust-version` stays at 1.99: baylee builds these crates
through the git revision and checks its own MSRV, 1.99, against them, so a
higher declared minimum here would fail baylee's `msrv` job. Clippy keeps
the code inside that minimum (`incompatible_msrv`).

- Clippy 1.100 widened `map_unwrap_or` to `map(..).unwrap_or_default()`;
  its 35 sites in 23 files now call `map_or_default`, which 1.99 already has
  (checked with rustc 1.99.0). Nothing else changed in the code, and nothing
  in `crates/central-crypto`, so `crypto-scope` keeps its fingerprint.
- The browser crypto module is rebuilt: a new compiler changes its bytes
  though not its source (new SHA-256 in `docs/xtask.md` §"The website's
  WebAssembly (`wasm`)" and in `crates/central-web/crypto/SHA256SUMS`).
  The Docker fallback in that section names `rust:1.100.0-bookworm` by
  digest, read from Docker Hub.
- Cargo's `trim-paths` is still unstable in 1.100, so the build host is still
  x86-64 Linux only.
