# The dependency upgrade of 18 November 2026

*Owner, 18.11.2026:* "alle crates upgraden (auch major versionen, führe
migration durch)", and in the form the same day "Ja, sqlx 0.9.1" after the
packages below were disclosed. The approval is the last entry of
`approved-packages.json`'s `approvals`.

## What moved

- **Direct dependencies.** `zeroize` 1.9.1 → 1.9.2 (every crate that wipes
  secrets), `ureq` 3.5.1 → 3.5.2 (`central-outbound`, `central-mail`,
  `central-web-server`), `regex` 1.13.1 → 1.13.2 (`xtask`), and the one
  major step: `jsonwebtoken` 11.1.0 → 12.0.0 with `jsonwebtoken-openssl`
  2.0.0 → 3.0.0 (`central-push`, the VAPID signature of Web Push). The push
  crate builds unchanged against them, and its test that verifies a VAPID
  token under the public key passes; `signature` 2.2.0, which only
  `jsonwebtoken` 11 needed, leaves the graph.
- **The lock file**, within each crate's own requirements: 34 packages, the
  ones that matter for the server being `sqlx` 0.9.0 → 0.9.1 (a pool that
  could spin a CPU, a PostgreSQL memory leak and a TLS flush that waited on
  incoming data are fixed), `rustls-webpki` 0.103.17, `rustls-pki-types`
  1.16.0, `webpki-roots` 1.0.12, `mio` 1.2.5 and `bytes` 1.12.2.
- **Removed with the first-party migration runner** (the commit before
  this one): `sea-orm-migration`, `sea-orm-cli`, `chrono` from every build,
  `bigdecimal`, `rust_decimal`, `borsh`, `ouroboros`, `nix`, `pgvector`,
  `tracing-subscriber` and 16 more.

## Held back, on purpose

- `opaque-sha2` (`sha2` 0.10.9) and `rand` 0.8.8 in `central-crypto`:
  `opaque-ke` 4.0.1, the newest, is built on `digest` 0.10 and `rand_core`
  0.6, and its record and protocol must not change under enrolled accounts.
- `getrandom-legacy` (`getrandom` 0.2.17 with `js`) in `central-web-crypto`:
  the browser backend for the crates still on `getrandom` 0.2 (the same
  OPAQUE stack).
- `leptos` 0.9.0-rc1: no later release was published.

## New code that is not this repository's, disclosed

- **`whoami` 2.1.3 gains its `std` feature** through `sqlx-postgres`
  0.9.1, which asks it for the operating system's user name as the default
  database user (Central always names its user, so the answer, if it
  is asked, is replaced). With `std` it calls the platform: on Linux, the server, its own
  `unsafe` calls of `libc` (`getpwuid_r` and the like; 32 lines name
  `unsafe` in the crate); before, it was a stub without any.
- **`objc2-core-foundation` 0.3.2 and `objc2-system-configuration` 0.3.2**
  (Zlib OR Apache-2.0 OR MIT): `whoami`'s way on Apple targets, foreign
  function bindings to Core Foundation and System Configuration. They are
  compiled on a Mac (a developer's build and tests) and never for the Linux
  server.
- **`libredox` 0.1.25** (MIT): `whoami`'s way on Redox, compiled for no
  target this repository builds.
- No build script is new. `libsqlite3-sys` 0.40.0 (the release that holds
  the fix for RUSTSEC-2026-0459) has one, and stays, like 0.37.0 before it,
  in the lock file only and in no build.

Licences: `cargo deny check` passes; `xxhash-rust`'s BSL-1.0 exception
moved from 0.8.19 to 0.8.21, the same licence. Advisories: `cargo audit
--deny warnings` passes with the `chrono` exception
([chrono-advisory](chrono-advisory.md)) in place of the SQLite one, which
ended ([sqlite-advisory](sqlite-advisory.md)).

This is the implementing agent's inventory, not a source audit of the
packages.
